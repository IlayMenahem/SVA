\section{Reinforcement learning}
\label{sec:rl}

We train the fine-tuned LLM with either GRPO or PPO~\citep{schulman2017ppo} with GAE~\citep{schulman2016gae}.

\subsection{The environment}

The agent performs best-first search in an environment with the following mechanics:

\begin{itemize}[nosep]
    \item \textbf{Initialization.} An episode starts from a SystemVerilog design and a target assertion to prove.

    \item \textbf{Action.} At each step the agent emits one typed action:
    \begin{itemize}[nosep]
        \item \texttt{ADD\_LEMMA(property, lemma\_assertion)};
        \item \texttt{ADD\_CUTPOINT(signal)};
        \item \texttt{ADD\_BLACKBOX(module)};
        \item \texttt{ADD\_COUNTER\_ABSTRACTION(module)};
        \item \texttt{RETRACT(property)};
    \end{itemize}
    The environment rejects actions that violate the schema, contain invalid SVA, reference unknown design objects, or introduce a cycle.

    \item \textbf{Soundness.} The environment tracks the design, proof DAG,
    transformation history, and status of every obligation, and enforces:
    \begin{enumerate}[nosep]
        \item a property may use a descendant as an assumption only after that
        descendant is proved;
        \item benchmark-supplied assumptions are external premises; assumptions
        from generated interface contracts become obligations discharged at the
        enclosing scope;
        \item cutpoints, abstractions, and blackboxes produce explicit equivalence
        or interface obligations and are usable only once those are proved;
        \item failed or timed-out obligations cannot support an ancestor;
        \item the target is accepted only when its entire dependency closure is
        proved.
    \end{enumerate}

    \item \textbf{Observation.} After each step the agent sees the full proof state,
    serialized as text:
    \begin{itemize}[nosep]
        \item the design source and the target property;
        \item the proof DAG: each obligation, its dependencies, and its status
        (proved, failed, or timed out);
        \item the applied transformations and the obligations they introduced;
        \item prover feedback for each failed obligation, either a counterexample trace
        projected onto the property's cone of influence or the timeout bound
        reached;
        \item the rejection reason, if the last action was invalid.
    \end{itemize}
    The design is pruned to the cone of influence of the open obligations, and
    counterexample traces are truncated to the cycles around the violation.

    \item \textbf{Termination.} The episode ends when the target is proved or a step limit is reached.
\end{itemize}

\subsection{Prover flow}
\label{sec:prover}

The environment requires a prover that parses SVA, discharges assertions unattended at scale, and supports cutpoints, abstractions, and blackboxing. We consider four candidates:
\begin{itemize}[nosep]
  \item \textbf{SymbiYosys + Verific (Tabby CAD Suite)}~\cite{symbiyosys}:
    full IEEE 1800 SVA via the Verific frontend; cutpoints and blackboxing map
    directly to Yosys passes; BMC, k-induction, and IC3 engines. Proprietary
    but free for academic use.
  \item \textbf{SymbiYosys (open-source frontend)}~\cite{symbiyosys}: fully
    open source, but parses only a subset of SVA, excluding the temporally
    deep properties in our corpus.
  \item \textbf{EBMC}~\cite{ebmc}: word-level BMC with k-induction; broader
    SVA coverage than open-source Yosys and trivial to deploy on a cluster,
    but weaker engine variety and no built-in cutpoint support.
  \item \textbf{Commercial tools (e.g., JasperGold, VC Formal)}: full SVA
    support and the most capable engines, but license seats constrain the
    parallel proof workers required by the RL loop.
\end{itemize}
We use SymbiYosys with Verific because it is the only free option that combines full SVA parsing, unattended operation, and native support for cutpoints and blackboxes. EBMC serves as a fallback for designs outside the Verific flow.

\subsection{Reward design}
The task reward at step $t$ is
\[
  r_t = R_{\mathrm{solve}}\cdot\mathbb{1}[\text{proved}] + \alpha\,\Delta P_t - \gamma\,U_t - \delta\,I_t,
\]
where $\Delta P_t$ is the number of newly discharged obligations, $U_t$ is the number of unresolved obligations introduced, $I_t$ is an invalid-action flag, and $R_{\mathrm{solve}} \gg \alpha, \gamma, \delta$. We treat the verifier cost $c_t = \widetilde{T}_t$ (normalized prover time) separately and bound it with a per-episode budget $B$ through Lagrangian relaxation:
\[
  r_t^{\lambda} = r_t - \lambda\,c_t, \qquad
  \lambda \leftarrow \max\!\big(0,\ \lambda + \eta\,(\hat{\mathbb{E}}[\textstyle\sum_t c_t] - B)\big),
\]
Here, $\hat{\mathbb{E}}[\sum_t c_t]$ is the mean episode cost over the current rollout batch. The budget $B$ increases with the curriculum (Section~\ref{sec:curriculum}), while $\lambda$ adapts automatically to keep the expected verifier time near that budget. This removes the need for a hand-tuned time-penalty weight.

\subsection{Designs and assertions for the environment}
\label{sec:rl-instances}

Each instance pairs a design with a target assertion that meets these conditions:

\begin{itemize}
    \item \textbf{Ground-truth provability}: the target is known to hold, so failures are attributable to the agent.
    \item \textbf{Sources}: we reuse the verified-SVA subset of the fine-tuning corpus from Section~\ref{sec:ft-sources}.
    \item \textbf{Splitting and leakage control}: we create a fixed,
    design-level partition and reuse it for both fine-tuning and RL. All
    assertions, generated variants, and proof traces derived from a design
    remain in the same partition: training uses only training designs, while
    validation and testing use disjoint held-out designs.
\end{itemize}

\subsection{Curriculum learning}
\label{sec:curriculum}

\textbf{Difficulty grading.} Each pair receives a static difficulty proxy based on the cone-of-influence state-bit count, hierarchy depth, and the property's temporal depth (the nesting of \texttt{\#\#}, \texttt{|->}, and unbounded operators). We calibrate the proxy against the baseline single-shot proof time and timeout rate, then divide the instances into tiers.

We use adaptive curriculum learning~\citep{bengio2009curriculum} to introduce more complex instances gradually.
